PHASE 5The audit loop — thirty passes minimum, exits only at zerome, autonomous, the quality gate for the whole build
ME

The rule, exactly as you set it: the finished app gets audited by independent passes — thirty minimum — and the loop does not end until a full audit round comes back with zero issues. If pass 30 still finds problems, there is a pass 31, 32, 40 — the loop closes itself, not the calendar.

ME

Each round = a squad of independent auditors, one lens each, across the real production app (not the mockup): visual fidelity to the locked system · both themes · three widths · every button actually wired · every cross-tab link lands · payment paths (pay, cap, overage, hold, release, refund) · the candidate journey end-to-end · the feed and every live listing · data consistency between tabs · security (no open endpoints, no leaked keys) · performance · copy · accessibility · error states · Night mode · phone. Test — every finding is logged with its fix and re-verified in the next round; nothing is closed by hand-waving. You get the round-by-round score: "Round 3: 14 found, 14 fixed. Round 4: 5 found…" until the round that reads zero.

ME

Regression protection: anything fixed once gets a permanent check so a later change can't quietly break it again — the loop only ever shrinks.
